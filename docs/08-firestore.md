# Firestore Collections

The frontend writes to two Firestore collections for analytics. Both are in the Firebase project `manifest-altar-490719-j7`.

## `sessions` Collection

Tracks user session duration. One document per session (a session ends on tab close, page hide, or logout).

**Document ID format:** `{uid}_{session_uuid}`

| Field | Type | Description |
|-------|------|-------------|
| `uid` | string | Firebase Auth user ID |
| `email` | string | User email |
| `display_name` | string | User display name |
| `started_at` | timestamp | When session began |
| `ended_at` | timestamp | When session ended (null if still active) |
| `active_minutes` | number | Non-idle time in minutes (excludes periods >2 min without activity) |
| `month` | string | Partition key, format `YYYY-MM` |

### How Session Tracking Works

- Session starts on page load (or when tab becomes visible again)
- Activity is tracked via: `mousemove`, `keydown`, `scroll`, `click`, `touchstart`
- If no activity for 120 seconds, user is marked idle (time stops accumulating)
- Session progress is saved to Firestore every 30 seconds
- Session closes on: tab hidden, page unload, or component unmount
- Each visibility change (tab switch) creates a new session

## `events` Collection

Tracks individual user interactions. One document per event.

**Document ID:** auto-generated by Firestore

| Field | Type | Description |
|-------|------|-------------|
| `uid` | string | Firebase Auth user ID |
| `email` | string | User email |
| `event_type` | string | Type of interaction (see below) |
| `metadata` | map | Event-specific data |
| `timestamp` | timestamp | When the event occurred |
| `month` | string | Partition key, format `YYYY-MM` |

### Event Types

| Event Type | Trigger | Metadata Fields |
|-----------|---------|----------------|
| `card_view` | User clicks a marker to view a battle card | `name`, `score`, `lat`, `lng` |
| `search` | User searches for an address (autocomplete or manual) | `query`, `lat`, `lng` |
| `filter_toggle` | User toggles "Hide Existing Customers" | `filter`, `enabled` |
| `fiber_toggle` | User toggles "Show Fiber Routes" | `enabled` |

## Querying Data

### Firebase Console

Navigate to: `https://console.firebase.google.com/project/manifest-altar-490719-j7/firestore`

### Example Queries (JavaScript)

```javascript
// Get all sessions for a user
const sessions = await getDocs(
  query(collection(db, 'sessions'), where('email', '==', 'user@dqe.com'))
);

// Get all card_view events this month
const events = await getDocs(
  query(collection(db, 'events'),
    where('event_type', '==', 'card_view'),
    where('month', '==', '2026-04'))
);

// Get total active minutes per user this month
const sessions = await getDocs(
  query(collection(db, 'sessions'), where('month', '==', '2026-04'))
);
```

## Notes

- Full per-user analytics (who viewed what) requires SSO to be enabled so users are properly identified
- Currently, users may be anonymous or have basic Firebase Auth — the `uid` and `email` fields will reflect whatever auth state exists
- The `month` field enables efficient queries by time period without scanning all documents
- Events are fire-and-forget — failures are logged to console but don't block the UI
